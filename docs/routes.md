# Routes

## 1. Principle

This is a single-discipline platform: everything on it is Counter-Strike 2. There is no
discipline segment in any URL, and no module prefix. A section of the site is a top-level
route.

The App Router is the pages layer (see [architecture.md](./architecture.md) §4.3). A page is a
folder, and everything that page alone needs lives inside it as FSD-named segments, using
Next.js private folders so the router ignores them:

```
app/(site)/teams/
  page.tsx              route entry — composes widgets, exports generateMetadata
  _ui/TeamCard.tsx      presentation used only by this page
  _lib/metadata.ts      metadata builder for this route
  [slug]/
    page.tsx
    _ui/TeamProfile.tsx
    _lib/metadata.ts
```

Segment names follow the same purpose-based convention as `src/`: `_ui` for presentation,
`_model` for route-local types and schemas, `_lib` for helpers. A block needed by a second
route moves down into `src/widgets` or below.

Helpers shared by every route live in `app/(site)/_lib`:

| File | Contents |
| --- | --- |
| `metadata.ts` | `buildMetadata`, `NOT_FOUND_METADATA` |
| `breadcrumbs.ts` | `trail`, `breadcrumbsJsonLd` |
| `params.ts` | `resolveSlug`, `resolveId` — validate and `notFound()` |

## 2. Route groups

```
app/
  layout.tsx        root layout — html, body, metadataBase
  (site)/           public site chrome: header with section nav, footer
    layout.tsx
    error.tsx       Client Component (React requirement)
    not-found.tsx
    loading.tsx
```

## 3. Route table

The section navigation in the site header is the route table. They are the same list, defined
once in `shared/config/routes.ts` as `MAIN_NAV`.

| Section | Route | URL | Data source |
| --- | --- | --- | --- |
| Обзор | `app/(site)/page.tsx` | `/` | live + upcoming + results + rankings + news |
| Новости | `app/(site)/news/page.tsx` | `/news` | local article source |
| — | `app/(site)/news/[slug]/page.tsx` | `/news/{slug}` | `NewsArticle` JSON-LD |
| Матчи | `app/(site)/matches/page.tsx` | `/matches` | `/csgo/matches/running` + `/upcoming` |
| — | `app/(site)/matches/[id]/page.tsx` | `/matches/{id}` | `/matches/{id}`, `SportsEvent` JSON-LD |
| Результаты | `app/(site)/results/page.tsx` | `/results` | `/csgo/matches/past` |
| Рейтинг | `app/(site)/rankings/page.tsx` | `/rankings` | Valve regional standings |
| Команды | `app/(site)/teams/page.tsx` | `/teams` | teams of running + upcoming tournaments |
| — | `app/(site)/teams/[slug]/page.tsx` | `/teams/{slug}` | `/teams/{slug}`, `SportsTeam` JSON-LD |
| Игроки | `app/(site)/players/page.tsx` | `/players` | `/csgo/players` |
| — | `app/(site)/players/[slug]/page.tsx` | `/players/{slug}` | `/players/{slug}`, `Person` JSON-LD |
| Ивенты | `app/(site)/events/page.tsx` | `/events` | `/csgo/tournaments/*`, tier `s,a,b` |
| — | `app/(site)/events/[slug]/page.tsx` | `/events/{slug}` | serie + stages, `SportsEvent` JSON-LD |

The URL segment is `events`, the entity is `tournament`. The segment follows the term the
audience uses; the model keeps the name [data-model.md](./data-model.md) gives it.

An event URL is a **serie** slug, not a stage slug. PandaScore models a tournament as a stage
(`Playoffs`, `Group A`), which is not what a reader calls a tournament. `getTournaments` groups
stages by serie so `Esports World Cup 2026` is one event rather than five.

Live matches are the one uncached read in the project: `getLiveMatches` calls `connection()`
instead of `use cache`, so it never enters the shell and always streams behind its own
`<Suspense>` boundary.

## 4. Dynamic parameters

All request-time APIs are Promises in Next.js 16. Every route awaits them, and every dynamic
route validates its params through `app/(site)/_lib/params.ts` before use:

```tsx
export default function Page(props: PageProps<"/teams/[slug]">) { ... }

async function TeamView({ params }: Pick<PageProps<"/teams/[slug]">, "params">) {
  const slug = await resolveSlug(params)
}
```

`PageProps` and `LayoutProps` are global helpers generated by `next typegen`, `next dev` or
`next build`. They are not imported. With `typedRoutes: true`, the route literal is checked
against the real route tree, so a renamed folder becomes a type error rather than a runtime 404.

Renaming or moving a route folder invalidates `.next/types`. Run `pnpm typegen` after any route
change, or `tsc` will report the old tree.

## 5. Loading and error boundaries

| File | Placement | Why |
| --- | --- | --- |
| `loading.tsx` | `(site)` | One navigation shell; finer boundaries go inside the page where the streaming split actually is |
| `error.tsx` | `(site)` | Must be a Client Component; recovers the segment without losing the root layout |
| `not-found.tsx` | `(site)` | Called explicitly by pages on unresolved slugs |

Under Cache Components the static shell renders before dynamic content arrives, so `loading.tsx`
is the navigation fallback and inner `<Suspense>` boundaries carry the streaming.

## 6. Rules

1. `app/` imports from `@/widgets`, `@/entities`, `@/shared` and — in the root layout only — `@/app`. Nothing in `src/` imports from `app/`.
2. A page's own components live in that page's `_ui`; they are promoted to `src/widgets` on their second consumer.
3. No route segment cache config (`dynamic`, `revalidate`, `fetchCache`, `dynamicParams`). Cache Components removed them; policy is set with `use cache` and `cacheLife` in the entity repositories.
4. Every dynamic route validates its params before use and calls `notFound()` on failure.
5. Route handlers exist only for machine callers. Pages never fetch from an internal route handler.
6. New routes are added to `MAIN_NAV` and `sitemap.ts` in the same change. See [seo.md](./seo.md).
